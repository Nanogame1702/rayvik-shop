# План реализации автоматической ежедневной рассылки

## 📋 Обзор

Добавление функционала повторяющихся рассылок в существующую систему отложенных рассылок Luno Shop бота.

## 🎯 Цель

Позволить администратору создавать рассылки, которые автоматически отправляются каждый день (или по другому расписанию) в заданное время.

## 📝 Детальный план

### Этап 1: База данных (30 минут)

**Файл:** `database.py`

**Задачи:**
1. Создать таблицу `recurring_broadcasts`:
   ```sql
   CREATE TABLE recurring_broadcasts (
       id INTEGER PRIMARY KEY AUTOINCREMENT,
       name TEXT NOT NULL,                    -- Название рассылки
       audience TEXT NOT NULL,                -- 'all' или 'buyers'
       text TEXT NOT NULL,                    -- Текст сообщения
       parse_mode TEXT DEFAULT 'HTML',        -- Режим парсинга
       keyboard_json TEXT,                    -- JSON с кнопками и медиа
       schedule_pattern TEXT NOT NULL,        -- 'daily', 'weekly', 'monthly'
       schedule_time TEXT NOT NULL,           -- 'HH:MM' в формате 24ч
       schedule_days TEXT,                    -- JSON массив дней для weekly [1,2,3]
       schedule_day_of_month INTEGER,         -- День месяца для monthly
       timezone TEXT DEFAULT 'Europe/Moscow', -- Часовой пояс
       is_active INTEGER DEFAULT 1,           -- Активна ли рассылка
       last_sent_at TIMESTAMP,                -- Когда последний раз отправлена
       next_send_at TIMESTAMP,                -- Когда следующая отправка
       total_sends INTEGER DEFAULT 0,         -- Счетчик отправок
       created_by INTEGER NOT NULL,           -- ID создателя
       created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
       updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
   )
   ```

2. Создать таблицу `recurring_send_log`:
   ```sql
   CREATE TABLE recurring_send_log (
       id INTEGER PRIMARY KEY AUTOINCREMENT,
       recurring_id INTEGER NOT NULL,
       sent_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
       status TEXT NOT NULL,                  -- 'success' или 'failed'
       error_message TEXT,
       recipients_count INTEGER,
       FOREIGN KEY (recurring_id) REFERENCES recurring_broadcasts(id)
   )
   ```

3. Добавить функции:
   - `init_recurring_tables()` - инициализация таблиц
   - `create_recurring_broadcast()` - создание
   - `get_recurring_broadcast()` - получение по ID
   - `list_recurring_broadcasts()` - список всех
   - `update_recurring_broadcast()` - обновление
   - `toggle_recurring_broadcast()` - включить/выключить
   - `delete_recurring_broadcast()` - удаление
   - `log_recurring_send()` - логирование отправки

## 🔄 Логика работы

```
1. Админ создает recurring broadcast
   ↓
2. Система создает запись в recurring_broadcasts
   ↓
3. Система рассчитывает next_send_at
   ↓
4. Система создает задачу в scheduled_broadcasts
   ↓
5. Планировщик отправляет рассылку в нужное время
   ↓
6. После отправки система:
   - Логирует результат в recurring_send_log
   - Обновляет last_sent_at и total_sends
   - Рассчитывает новый next_send_at
   - Создает новую задачу в scheduled_broadcasts
   ↓
7. Цикл повторяется, пока рассылка активна
```

## 🚨 Важные моменты

1. **Timezone handling**: Всегда использовать `ZoneInfo` для работы с часовыми поясами
2. **Atomic operations**: Обновление статистики и создание следующей задачи должны быть атомарными
3. **Error handling**: При ошибке отправки все равно создавать следующую задачу
4. **Cleanup**: При удалении recurring broadcast удалять и связанные scheduled tasks
5. **Validation**: Проверять корректность времени и дней перед сохранением
