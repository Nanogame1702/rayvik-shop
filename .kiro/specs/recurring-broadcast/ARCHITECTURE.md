## 🔀 Взаимодействие компонентов

### Создание рассылки:
```
User → Handler → Service → Database
                    ↓
                Scheduler (создание задачи)
```

### Отправка рассылки:
```
Scheduler → Database (получение задачи)
    ↓
Telegram API (отправка)
    ↓
Service (обработка результата)
    ↓
Database (логирование + создание следующей задачи)
```

### Управление рассылкой:
```
User → Handler → Database (обновление)
                    ↓
                Scheduler (пересчет расписания)
```

## 🕐 Расчет следующей отправки

### Daily (Ежедневно):
```python
def calculate_next_daily(current_time, schedule_time, timezone):
    """
    Пример: Сейчас 2025-11-27 15:00, schedule_time = "09:00"
    
    1. Парсим schedule_time → 09:00
    2. Создаем datetime на сегодня в 09:00
    3. Если время уже прошло → добавляем 1 день
    4. Результат: 2025-11-28 09:00
    """
    next_time = current_time.replace(
        hour=schedule_time.hour,
        minute=schedule_time.minute,
        second=0,
        microsecond=0
    )
    
    if next_time <= current_time:
        next_time += timedelta(days=1)
    
    return next_time
```

## 🔐 Безопасность

1. **Проверка прав:** Все команды доступны только ADMIN_ID
2. **Валидация данных:** Проверка формата времени, дней, текста
3. **SQL Injection:** Использование параметризованных запросов
4. **Rate limiting:** Ограничение частоты создания рассылок
5. **Логирование:** Все действия логируются для аудита

## 📈 Масштабируемость

- **Количество рассылок:** Неограниченно (в рамках SQLite)
- **Количество получателей:** Зависит от Telegram API limits
- **Частота отправки:** Минимум 1 минута между рассылками
- **Хранение истории:** Рекомендуется очистка старых логов (>90 дней)
